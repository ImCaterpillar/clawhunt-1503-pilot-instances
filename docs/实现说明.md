# 实现说明 — #1503 客户 Agent 试点实例

## 需求还原

企业知识库与多 Agent 协作系统（系列 50 单）的拆单之一。本单范围：
**基于统一模板配置五个隔离的试点实例，使用授权或脱敏材料**。

验收标准：**提供五个实例配置及互相隔离的验证记录**——即：
1. 有统一模板（证明是同源可配置复用）；
2. 有 5 个实例（证明配置化覆盖多行业）；
3. 实例间**互相隔离**（实证性要求，必须能跑出"读不到对方"的测试）。

## 设计

### 1. 统一模板

`schema/instance.schema.json`（draft-07）定义实例结构：
- `instance_id`（全局唯一，`inst-` 前缀 + 模式约束）
- `instance_name` / `industry`（8 行业枚举）
- `namespace_prefix`（**隔离关键**：全局唯一，`ns-` 前缀）
- `bot_role`（职责 + 升级策略）
- `knowledge_mounts`（知识挂载：来源/读写权限）
- `data_domains`（数据域 + 作用域）
- `tools`（工具权限：read/write/deny 三档）
- `additionalProperties: false` —— 拒绝未定义字段，防止实例配置随意膨胀

八个必填字段逐一有约束，同模板可配置化复用。

### 2. 五个隔离实例

| 实例 | 行业 | 命名空间 | 差异化 |
|---|---|---|---|
| inst-gold-jewelry-01 | 黄金珠宝 | ns-gold-01 | 品控/工艺规则 + 报价工具 |
| inst-apparel-02 | 鞋服制造 | ns-apparel-02 | 版型库 + 排产计划 |
| inst-healthcare-03 | 医疗健康 | ns-health-03 | 科普预约 + 合规边界 |
| inst-woodwork-04 | 硬木家具 | ns-wood-04 | 榫卯工艺 + 可制造性 |
| inst-culture-05 | 非遗文创 | ns-culture-05 | IP 授权 + 内容合规 |

知识挂载、数据域、工具权限按行业差异化，证明"一套模板、按配置切换"。
所有材料为脱敏样例（无真实客户/患者/工厂机密），符合原文"使用授权或脱敏材料"。

### 3. 命名空间隔离（验收核心）

```
命名空间 = namespace_prefix（每实例全局唯一）
存储     = registry[prefix] -> set(data_keys)
读写规则：
  write(instance_id, key)      -> 写入该实例前缀命名空间
  read(requester, target)      -> 仅当 requester==target 返回数据
                                  否则返回空集 + 审计
```

关键决策：
- **隔离靠 namespace_prefix 硬分隔**，而非靠"意识"——跨实例读在
  数据结构上就不可能命中对方前缀；
- **跨实例读返回空集 + 审计**，不抛错——不泄露对方"存在数据"的事实
  （防侧信道），又能追踪越权尝试；
- **全局唯一前缀由 register() 强制**：新实例若用已占用的前缀直接抛
  `InstanceError`（测试 10b），从源头杜绝两个实例共享命名空间。

### 4. 校验器

`instance_loader.py` 内置迷你 JSON Schema draft-07 必要子集校验器
（type/required/properties/additionalProperties/items/enum/pattern/
minLength/maxLength/minItems），零第三方依赖，与 #1489/#1490 同风格。
反例 `inst-invalid-99.json` 故意带缺字段/额外字段/冲突前缀/真实联系
方式，验证 schema 与注册器都会拒绝（测试 10/10b）。

### 5. 交叉访问验证

`cross_access_check(requester, target)` 返回 `(leaked, total)`：
- total = 目标实例实际写入的数据条数
- leaked = requester 能读到的条数（必须恒为 0）

测试 7 遍历全部 C(5,2)×2 = 20 个有向对，断言累计 leaked=0；
测试 8 自读断言每实例 leaked==total==3。
